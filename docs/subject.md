# Subject summary

## Goal

Build a complete, playable Pac-Man in Python with object-oriented code, a simple
graphical library, and a modular architecture. Then package and publish it.

Game loop: **Main Menu > Start > Win or Lose > Enter name > Main Menu**.

A graphical library counts as "similar to MLX" only if every function used has
an MLX equivalent.

## Technical constraints

- Python 3.10 or later.
- `flake8` clean.
- Type hints on parameters, return values and variables where applicable. `mypy`
  must pass without errors.
- Docstrings on functions and classes, PEP 257 style.
- Exceptions handled with `try`/`except`; use context managers for files and
  other resources. A traceback during review means the project is
  non-functional.
- No resource leaks.

## Makefile

Mandatory rules:

| Rule | Behavior |
|---|---|
| `install` | Install dependencies (pip, uv, pipx, ...) |
| `run` | Run the main script |
| `debug` | Run the main script under `pdb` |
| `clean` | Remove `__pycache__`, `.mypy_cache`, and similar |
| `lint` | `flake8 .` and `mypy . --warn-return-any --warn-unused-ignores --ignore-missing-imports --disallow-untyped-defs --check-untyped-defs` |
| `lint-strict` | Optional: `flake8 .` and `mypy . --strict` |

Also recommended: a `.gitignore` for Python artifacts, a virtual environment,
and extra `pytest`/`unittest` tests (not graded).

## Usage

```bash
python3 pac-man.py config.json
```

- Exactly one argument, a JSON config file. The filename is free.
- Missing file, invalid value or missing key: clean message, never a traceback.

## Config file

JSON plus comments: lines starting with `#` are ignored. Other comment styles
may be supported. The structure is free but must be documented in the README
with defaults.

Suggested keys:

- `highscore_filename`
- `level`: array of levels, each with `width` and `height`
- `lives`: 3
- `pacgum`: 42
- `points_per_pacgum`: 10
- `points_per_super_pacgum`: 50
- `points_per_ghost`: 200
- `seed`: 42
- `level_max_time`: 90

Faulty values are clamped to safe defaults, a clear message is logged, and the
game continues. Unknown keys are ignored. The config is edited live during the
defence.

## Maze generator

- Use the assigned A-Maze-ing package from another group, unmodified. It is
  re-installed during peer review.
- Adapt your loader to their interface, never the reverse.
- `PERFECT = False`, so corridors are Pac-Man compatible.
- Handle generator failures cleanly.

## Highscores

Persistent storage, implementation free but documented in the README. Must:

- Survive a missing or invalid file.
- Accept player names: max 10 characters, alphanumeric and spaces only.
- Accept scores: non-negative integers.
- Keep the top 10, names and scores.
- Load at game start, save at game end.
- Ask for a name on win or lose.
- Show the highscores in the main menu.

## Level structure

- Maze generated by the assigned package.
- First level uses a fixed seed (for example 42); later levels are random.
- Pacgums in most corridors.
- Super-pacgums in the 4 corners.
- 4 ghosts, one per corner.
- Player starts in the middle.

## Player

- Moves through corridors only, never through walls.
- Four directions, arrow keys or WASD.
- Starts with 3 lives; loses one when a ghost touches it.
- Respawns in the middle after losing a life.
- Game over when no lives remain.
- Wins the level when every pacgum is eaten; wins the game when every level is
  done.
- Pacgum gives X points, super-pacgum gives Y points and makes ghosts edible for
  a short time, edible ghost gives Z points.

## Ghosts

- Move autonomously through corridors.
- Chase the player when not edible. The chase algorithm is your choice.
- Flee when edible.
- Respawn in their corner after a while when eaten (for example 5 to 10
  seconds).

## Cheat mode

Exists to make peer review easy. Suggested features: invincibility, level skip,
ghost freeze, extra lives, increased speed, anything else useful.

## Scoring

Score only increases: pacgum +X, super-pacgum +Y, edible ghost +Z. It never
decreases.

## Progression

- At least 10 levels.
- Each level has a time limit (for example 90 seconds). On timeout, choose the
  behaviour (restart the level, end the game, ...) and document it.
- Score and remaining lives carry between levels.
- Game ends when all levels are done or all lives are lost.
- Pause and resume during play.

## User interface

- **Main menu:** Start Game, View Highscores, Instructions, Exit.
- **HUD, always visible:** score, lives, current level, remaining time.
- **Pause menu:** Resume, Return to main menu.
- **Game over screen:** final score and name entry for the highscores.
- **Victory screen:** final score, congratulation, name entry.

## Packaging

- A fully functional build published free but unlisted/private on Steam,
  Itch.io or similar.
- Minimal in-package instructions: controls, options, configuration.
- Git repository holds the full source and the packaging script/spec at the
  root.
- The package may have to be regenerated during review.

## Project management

Keep evidence in a dedicated repository subdirectory: timeline or Gantt,
planned versus actual progress, analysis and choices, risks and mitigation,
team organization, acceptance test plan, blocking points and conflicts.

Required sections:

- **Description**: goal and overview.
- **Instructions**: compilation, installation, execution.
- **Resources**: references and how AI was used, for which tasks and parts.
- **Configuration**: keys, structure, defaults.
- **Highscore**: how it works and why this design.
- **Maze Generation**: how the assigned package is used.

- **General Software Architecture**: modules, classes, relationships.
- **Project Management**: approach and link to the management directory.
